k8s Lab Intro

A brief overview of the k8s lab setup.

Introduction

While I have been using a managed k8s cluster through work, it was being managed by a different team. I wanted to stand up my own k8s cluster to learn how all of these pieces fit together. I felt this was fundamentally important to my career. I should have a reasonable understanding of the platform I interact with all the time.

Software versions

Development in this space is moving very rapidly. While trying to follow other guides only months old, I was hitting out-of-date information. That is part of the reason for this lab, to try and build something with the latest possible and bridge some of the gaps I’ve seen in online information.

North Star

For any good lab, you need some kind of goal to build towards. That goal can keep changing with discovery, but without anything you’re just looking at a blank sheet of paper. The goal helps focus the ideas and energy so you don’t go off in a million directions all at once. If you do that, no work will ever get accomplished. For my North Star was to try and build out a full Factorio Helm chart / server deployment.

Software

  • Hypervisor:

    • Proxmox: I had used Proxmox in the past and found it really intuitive as a free to use Hypervisor. This was an easy choice.
      • A note about my implementation. I originally only started up one server, but was able to cobble together some parts and bring a second one up. This has me running them as two stand-alone hypervisors. From a lab perspective, I could have spun the VMs up on NFS or iSCSI, to allow for Live Migration, but I had a lot of disks. I figured might as well leverage that storage and save the network storage for the k8s PVCs.

  • OS:

    • Talos Linux:
      • Version: v1.14.2
      • Description: It’s an immutable and minimal OS that is purpose built with k8s running right out of the box. I chose this because I wanted to get the OS out of the way. I’ve configured enough servers that I didn’t want to burn time tracking down sysconfig settings and debugging SELinux alerts.

  • Kubernetes:

    • Client Version: v1.37.1
    • Kustomize Version: v5.8.1
    • Server Version: v1.37.0

  • k9s: Version: v0.51.0 Description: This is an incredible tool for interacting with k8s clusters. I would consider this a must install CLI tool. It allows you to visualize so much cluster information at once it.

  • Helm:

    • Client Version: v4.3.1
    • Description: Helm is a package manager for k8s. It allows you to build up template workflows where you can apply a set of values to build out a deployment. You can also leverage exiting templates to install complete solution stacks.

Internet

Internet is nothing special. Just consumer cable broadband, with a random IP that’s fairly static unless there is some maintenance that kicks my modem off the provider.

Router

The router is a Ubiquity UCG-Max. While the k8s lab was not a consideration when I purchased this, it has proven to be very helpful in extending the lab. Some features that I have been able to leverage with different deployments:

  • BGP Advertisements: Using Cilium I am able to create Load Balancer IPs that are advertized to the router. This allows me to directly connect to the 172.16.0.0/16 subnet through the advertized routes. It is even possible to port-forward from the router to these advertised routes.

  • External DNS Unifi Webhook: This is a webhook provider for the External DNS CRD. You create an API Key on your router and then add it to a webhook config. Then when you supply the annotations like:

     service:
   annotations:
     lbipam.cilium.io/ips: 172.16.0.101
     external-dns.kubernetes.io/hostname: factorio-test-01.home.arpa

    This will automatically trigger a webhook to create a DNS A record for the above hostname and IP. If you delete it, the record is cleaned up automatically.

Tip

Just like in the above situation, you can often find multiple projects with overlapping functionality. It is important to look at how active these repositories are. One that’s 8 years old without any activity is likely not going to have a broad adoption. This translates into fewer resources that will have used it and documented problems / solutions on sites like Stackoverflow. This is something I always consider, especially if I’m going to find myself as the sole solution provider for the technology of choice.
